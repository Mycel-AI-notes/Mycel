## P0 — потеря данных пользователя

### 1. Переименование заметки не обновляет `[[ссылки]]`

`src-tauri/src/commands/notes.rs:note_rename` делает `fs::rename` и правит
только `tree-order.json`. Ни одного места в кодовой базе, которое перезаписывало
бы `[[Old Name]]` → `[[New Name]]` (проверено grep'ом по всему репо).

Последствия: переименовал заметку — все ссылки на неё во всём vault молча
сломались. Бэклинки исчезли, граф распался, в редакторе ссылки стали
«broken». Восстановить можно только вручную.

Это функция №1, на которую опираются в Obsidian. Без неё vault деградирует
тем быстрее, чем активнее им пользуются.

**Фикс:** перед `fs::rename` собрать все заметки, где `wikilinks` резолвятся
в старый stem, и перезаписать их. Учесть формы `[[Name]]`, `[[Name|alias]]`,
`[[folder/Name]]`, `[[Name#heading]]`, `![[Name]]`. Для папок — рекурсивно по
всем детям. Плюс диалог «обновить N ссылок в M заметках?».

### 2. Создание / переименование / перетаскивание перезаписывает существующий файл

Три пути, ни в одном нет проверки существования цели:

- `note_create` → `note_save` → `fs::write` — **усекает** существующий файл и
  пишет туда `# Name\n\n`. `FileTree.commitCreate` тоже не проверяет дерево.
  Создал заметку с именем уже существующей в той же папке → её содержимое стёрто.
- `note_rename` → `fs::rename` — на Unix молча заменяет цель. Переименовал
  `b.md` в `a.md` → `a.md` уничтожен.
- `FileTree.moveEntry` → `renameNote(src, joinPath(destParent, srcName))` —
  перетащил `notes.md` в папку, где уже есть `notes.md` → старый уничтожен.

Ни подтверждения, ни undo, ни корзины. Самый вероятный сценарий из трёх —
drag&drop: две папки, в каждой `index.md` или `notes.md`.

**Фикс:** в бэкенде вернуть ошибку при `abs_path.exists()` для `note_create`
и `note_rename` (+ отдельный флаг `overwrite: bool` для явного согласия);
в UI — либо автосуффикс ` 2`, либо диалог «файл существует: заменить /
переименовать / отмена».

### 3. Нет автосохранения, и несохранённое теряется молча

`MarkdownEditor` пишет на диск только по `Mod-s` и по кнопке Save. Нигде нет
ни автосейва по таймеру/блюру, ни `onCloseRequested`, ни `beforeunload`
(проверено grep'ом).

Три способа потерять текст:
- Закрыть таб с точкой «несохранено» — `closeTab` просто выкидывает его без вопроса.
- Закрыть приложение — всё несохранённое уходит.
- `handleSave` ловит ошибку и делает только `console.error` — если запись
  упала (диск, залоченный крипто-vault), пользователь видит «сохранил», а на
  диске ничего нет.

Отдельно неприятное: `closeTab` не чистит `noteCache`, поэтому при повторном
открытии таба возвращается несохранённый текст **с флагом `isDirty: false`**.
Индикатор врёт: пользователь уверен, что сохранено, а на диске старая версия.

**Фикс:** автосейв с дебаунсом ~1–2 с (как в Obsidian) + сейв на смену таба и
на `onCloseRequested`; тост при ошибке записи вместо `console.error`.

### 4. Переименование папки «воскрешает» старый путь

`useVaultStore.renameNote` патчит только таб, чей `path === oldPath`. При
переименовании (или перетаскивании) папки открытые табы её детей сохраняют
старые пути `old/child.md` вместе с валидным `disk_hash` в кэше. Следующий
Cmd+S идёт в `write_note`, который делает `create_dir_all(parent)` — старая
папка создаётся заново, и заметка раздваивается: часть контента в новой папке,
часть в воскрешённой старой.

**Фикс:** в `renameNote` переписывать пути всех табов и ключей `noteCache`
с префиксом `oldPath + '/'`.

## P1 — важные

### 5. Ссылки с алиасом ведут не туда и плодят мусор

`MarkdownDecorations.ts:282` рендерит в виджет **алиас**: `const label = (m[2] ?? m[1])`.
`WikilinkNavigation.ts` читает `el.textContent` — то есть алиас — и резолвит
его как имя заметки. Для `[[Deep Learning|мои заметки]]`: резолв «мои заметки»
не находит ничего → `createNote('мои заметки.md')` в корне vault.

То есть каждый клик по ссылке с алиасом вместо перехода создаёт новую пустую
заметку. Alias-ссылки в Mycel сейчас нерабочие.

**Фикс:** хранить target в `data-target` на виджете и читать его в хендлере.

### 6. Синк коммитит `.mycel/` — AI-индекс с открытым текстом заметок уезжает на GitHub

`core/sync.rs:DEFAULT_GITIGNORE` = `.DS_Store`, `Thumbs.db`, `*.swp`, `*.swo`.
`.mycel/` там нет, а `stage_and_commit_all` делает `index.add_all(["."])`.

Значит в приватный GitHub-репозиторий уходит:
- `.mycel/ai/index.db` — SQLite со **всеми чанками всех заметок в открытом
  виде** + эмбеддинги. Бинарный блоб, меняется при каждой переиндексации —
  история git пухнет на десятки МБ.
- `.mycel/ai/quick_filing_log.jsonl` — тела заметок (до 2000 символов) в plaintext.
- `.mycel/ai/config.json`, `insights.json`, `sync.json`, `garden/*`.

Комментарии в самом коде исходят из обратного: `filing_log.rs:12` пишет
«we assume the user will gitignore `.mycel/`», `insights/store.rs:3` — «so a
paranoid user…». README тоже говорит «Add it to `.gitignore` if you sync the
vault with Git separately» — но собственный синк этого не делает.

Особенно плохо в связке с per-note encryption: индексер корректно
**не** индексирует `.md.age` (проверено, есть тест `encrypted_files_are_skipped`),
но всё незашифрованное всё равно лежит в plaintext-индексе, который улетает в git.

**Фикс:** добавить `.mycel/` в `DEFAULT_GITIGNORE`; для уже
сконфигурированных vault'ов — миграция (`git rm -r --cached .mycel`) и
предупреждение, что историю надо чистить самому.

### 7. Нет валидации пути в `note_read` / `note_save` / `note_create` / `folder_create`

`is_safe_rel_path` есть и применяется в `note_delete`, `note_rename`,
`quick_note_suggest` — но не в read/save/create. `vault_root.join(path)` с
`../` спокойно выходит за пределы vault.

И это не теоретически: путь достижим из **содержимого заметки**. Ссылка
`[[../../../.ssh/authorized_keys]]` → `resolveWikilink` не находит →
`createNote('../../../.ssh/authorized_keys.md')` → запись за пределы vault.
В расшаренном/синканутом vault это чужой контент.

**Фикс:** прогнать все четыре команды через `is_safe_rel_path`, плюс
санитизировать label в `WikilinkNavigation`.

### 8. Insights: повторный прогон при каждом старте + лимиты «для теста»

- `scheduler.rs:74` — `last_run_date` инициализируется `None` и нигде не
  читается из стора, хотя `commands/ai/insights.rs:110` отдаёт `last_run_at`
  из БД. При `catch_up: true` (дефолт) каждый запуск приложения после 07:00
  снова гоняет полный pipeline: `bulk_reindex` всего vault + все детекторы.
  Реиндекс — это платные вызовы эмбеддингов за каждую изменённую заметку.
  Открыл-закрыл приложение пять раз — пять прогонов.
- `settings.rs:105` — `max_per_day: 500, max_per_kind: 200` с собственным
  комментарием «TODO: dial back to 10 / 3 before release». 500 карточек в день
  завалят пользователя.
- `scheduler.rs` хардкодит `has_llm: false`, поэтому любой детектор с
  `requires_llm()` вообще не запускается — мёртвый код до «Phase 3+».

Смягчает то, что Insights по умолчанию выключены.

### 9. Удаление безвозвратно

`note_delete` → `fs::remove_file` / `fs::remove_dir_all`. Для папки это
рекурсивное уничтожение всего содержимого после одного `confirm()`. Ни
`.trash/`, ни системной корзины, ни undo. В Obsidian это настройка с тремя
вариантами, и дефолт — не «permanently».

### 10. Бэклинки для зашифрованных заметок никогда не находятся

`backlinks_get` берёт `Path::new("a.md.age").file_stem()` = `"a.md"`, и
сравнивает с stem'ами ссылок (`"a"`). Никогда не совпадёт. Плюс цикл
пропускает сами `.md.age` как источники ссылок.

## P2 — производительность (сейчас незаметно, на 2k+ заметок больно)

Общий корень: **нет индекса.** `notes_list`, `backlinks_get`, `notes_by_tag`,
`graph_data`, `dbs_list` при каждом вызове заново обходят весь vault, читают
и парсят каждый `.md` (regex + gray_matter).

### 11. Каждое сохранение = полный обход vault
`RightPanel.tsx:72` — эффект с `backlinks_get` зависит от `vaultVersion`,
который бампается на каждом `saveNote`. Cmd+S → полный обход + парсинг всего
vault. Плюс то же на каждое переключение таба.

### 12. `WalkDir` заходит в `.git` и `.mycel`
6 из 10 мест с `WalkDir::new` идут без `filter_entry` (`search.rs` ×3,
`graph.rs`, `database.rs:503`, `crypto.rs:774`) и фильтруют скрытое
**после** обхода по `rel.contains("/.")`. На синканутом vault это означает
рекурсивный обход `.git/objects` — десятки тысяч файлов — на каждый вызов.
`indexer.rs`, `attachments.rs` и `notes.rs:629` сделаны правильно, через
`filter_entry` — есть с чего копировать.

### 13. Каждый клик по wikilink = `notes_list` по всему vault
`resolveWikilink` дёргает `notes_list` (обход + парсинг всех заметок) на
каждый клик по ссылке. Кэша нет.

### 14. `quick_note_suggest` реиндексирует весь vault
На каждое сохранение быстрой заметки: `bulk_reindex` всего vault под
`ai.indexing` lock. Хеш-скип спасает от повторных платных вызовов, но не от
чтения и хеширования каждого файла.

### 15. Учёт стоимости захардкожен под одну модель
`embedder.rs:75` — `PRICE_PER_MILLION: f64 = 0.02` (цена
`text-embedding-3-small`), при этом `embedding_model` и `chat_model`
настраиваемые. Сменил модель — `daily_budget_usd` считает неправильно.

## Инфраструктура

### 16. `npm run lint` не работает
ESLint 8 ищет `.eslintrc*`, в репо нет ни одного конфига. `npm run lint`
падает с `ESLint couldn't find a configuration file`. При этом и README
(«npm run lint before pushing»), и PR-шаблон требуют его как чеклист-пункт.
Любой контрибьютор спотыкается на первом же шаге.

### 17. `cargo fmt --check` падает в 38 файлах
158 диффов. Тоже пункт PR-шаблона.

### 18. CI нет вообще
`.github/` содержит только `PULL_REQUEST_TEMPLATE.md`. Четыре обязательных
по шаблону проверки не гоняются нигде, кроме честного слова автора PR.

### 19. Тесты
111 Rust-тестов — это хорошо, но 31 из 54 файлов без тестов, включая
фундамент: `core/parser.rs`, `core/vault.rs`, `core/watcher.rs`,
`core/garden.rs` (958 строк!) и **все** `commands/*`. На фронтенде тестов 0 —
ни vitest, ни testing-library, а вся логика табов/конфликтов/кэша живёт в
`stores/vault.ts` (782 строки), где как раз и сидят баги P0 #3 и #4.

### 20. Дублирование в `stores/vault.ts`
`openNote` / `openGardenTab` / `openInsightsTab` / `openImageTab` — четыре
почти идентичных блока по ~40 строк логики preview/pin. Логика конфликтов
в `resolveConflictReload/KeepMine/KeepBoth` — ещё три копии одного и того же
обновления кэша. ~250 строк можно свести к двум хелперам, и тогда правка
бага #4 делается в одном месте вместо пяти.

## Точки роста

### Главный продуктовый пробел: нет полнотекстового поиска по vault

Инвентаризация поиска в Mycel:
- Quick switcher (`⌘O`) — fuzzy **только по заголовкам и путям**.
- Поиск внутри заметки — есть (CodeMirror `@codemirror/search`).
- Поиск по тегам — есть.
- Семантический поиск — есть, но требует OpenRouter API-ключ и **платит за
  каждый запрос**.

Поиска по **содержимому** заметок нет вообще — ни команды в бэкенде, ни UI.
В Obsidian это ядро продукта (`⌘⇧F`, операторы `path:`, `tag:`, `line:`,
`file:`, OR/`-`). Пользователь, у которого 500 заметок, не может найти фразу,
которую точно помнит, — если не платит за эмбеддинги. Это единственный гэп,
который в одиночку блокирует переход с Obsidian.

Хорошая новость: `rusqlite` с `bundled` уже в зависимостях, а SQLite FTS5
идёт в bundled-сборке. Полнотекст можно построить на той же `.mycel/ai/index.db`
без новых зависимостей, бесплатно и локально. И тот же индекс снимает всю
проблему P2 (бэклинки, теги, граф, `notes_list` — запросы, а не обходы).

### Остальные пробелы против Obsidian
- **Нет командной палитры** (`⌘P`) — весь функционал доступен только мышью
  или через 8 захардкоженных хоткеев в `App.tsx`. Настройки хоткеев нет.
- **Embeds `![[Note]]` не рендерятся.** Парсер их распознаёт (`is_embed`), UI
  игнорирует (`RightPanel.tsx:113` — `if (wl.is_embed) continue`). Трансклюзии нет.
- **Нет `aliases` в frontmatter.** Резолв ссылок только по stem/title/суффиксу.
- **Нет daily notes и шаблонов** — в slash-меню ни того, ни другого.
- **Нет unlinked mentions** — Obsidian показывает упоминания названия без ссылки.
- **Нет локального графа** — только глобальный на весь vault.
- **Нет закладок/избранного**, нет панели unresolved links.
- **Нет редактора frontmatter** (properties) — только сырой YAML.
- **Нет reading mode** — есть только live-preview-декорации.
- **Нет плагинного API** — а это то, чем Obsidian реально держит пользователей.
- **Нет мобильного** (в роадмапе).

### Где Mycel уже сильнее Obsidian
Это важно не потерять, это и есть дифференциация:
- **Inline-базы (`mycel-db`)** с типизированными колонками — у Obsidian этого
  нет из коробки (Dataview только читает, не редактирует).
- **Per-note age-шифрование** с двухфакторной обёрткой и keyring — у Obsidian нет.
- **Garden / GTD** (inbox → actions → projects → waiting → someday + weekly
  review) как встроенный модуль.
- **Quick-note auto-filing** — LLM решает, куда положить быструю заметку.
- **Present mode** — любая заметка как слайды.
- **Настоящий Rust-бэкенд** вместо Electron.
- **AGPL + CLA** — открытость с заделом под коммерческую редакцию.

### Архитектурные точки роста
1. **Индекс как единый источник правды.** SQLite FTS5 + таблица links/tags.
   Инкрементальное обновление из `core/watcher.rs` (он уже есть и работает).
   Закрывает и поиск, и всю производительность.
2. **Локальные эмбеддинги.** Сейчас любой AI = OpenRouter = платно = барьер
   входа. Роадмап обещает Ollama/llama.cpp — это то, что сделает AI-историю
   реально используемой, а не опциональной.
3. **Плагинный API.** Главный ров Obsidian. Даже минимальный (slash-команды,
   панели, декорации) меняет динамику.
4. **Трейт-абстракция для LLM-провайдера.** `openrouter.rs` захардкожен;
   `embedder.rs` уже трейт — надо то же для chat.

## Что делаем дальше — рекомендация

**Спринт 0 — «не терять данные» (1 неделя).** Это не обсуждается, это выход
из альфы. P0 #1–#4 + P1 #5, #6, #7. Плюс инфра #16–#18: eslint-конфиг,
`cargo fmt`, и CI-воркфлоу с четырьмя проверками из PR-шаблона — иначе
следующий баг придёт тем же путём.

**Спринт 1 — «индекс» (1–2 недели).** SQLite FTS5 в существующей
`.mycel/ai/index.db`, инкрементально из watcher'а. Даёт полнотекстовый поиск
(`⌘⇧F` с операторами) и попутно убивает все P2. Это самый высокий
value/effort в проекте.

**Спринт 2 — «привычки Obsidian-пользователя» (1–2 недели).** Командная
палитра `⌘P`, настраиваемые хоткеи, daily notes + шаблоны, embeds/трансклюзия,
`aliases`, unlinked mentions, локальный граф, корзина (#9).

**Только потом** — глубокое исследование Obsidian, чтобы «превзойти». Сейчас
это преждевременно: пока переименование заметки ломает ссылки, а найти
фразу в своих записях нельзя, никакая уникальная фича не удержит человека,
пришедшего из Obsidian. Сначала паритет по гигиене, потом уже рычаги
дифференциации (inline-базы, шифрование, Garden, локальный AI, плагины).

Полезно к этому моменту иметь свой vault на 500+ заметках и прожить на
Mycel неделю — половина этих баг-репортов пришла бы сама.
